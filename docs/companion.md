# dsh-pet 伙伴陪玩 · 0.2.1

## 安装与使用

验证组合：DSH **0.2.2-rc.1**、[dsh-pet **0.4.7**](https://github.com/PC2005-cloud/dsh-pet)、AgentGamer **0.2.1**。dsh-pet 是可选插件，不是自动安装依赖。两个插件必须在同一 DSH Host／profile 启用；分别运行的两个 DSH 无法共享这次联动。

1. 在 DSH 添加插件时输入npm包名 `dsh-agentgamer`，或安装Release中的本地tgz，按提示重启。桌面版与浏览器版的命令示例见 [安装说明](../README.md#安装)。原有 dsh-pet 保持用户自己的配置，AgentGamer 不会自动升级或修改它。
2. 在 AgentGamer 大厅选择对战模型，点“我的桌宠”→“刷新桌宠”，按种类和实例 ID 选择宠物。同名宠物通过 `entry / petId` 区分。
3. 点“预览接入资料”，核对人设和近聊。再点“连接桌宠”，开始 21 点或双人吹牛骰。
4. 完整比赛结束后可展开“公开战报预览”。只有点击“告诉桌宠”，才调用它的聊天模型、生成回复，并写入其聊天记忆。返回的文字在平台聊天中标为“战报回应”。

游戏使用 AgentGamer 当前选择的模型与思考设置；读取伙伴资料不调用模型。战报回应使用 dsh-pet 自己配置的聊天模型，产生额外模型用量。普通对手模式无需 dsh-pet。

缺少插件、接口不兼容、实例已删除、来源读取失败都会显示原因，可刷新或重试。比赛开始后使用固定资料快照，即使桌宠来源离线也可完成本场；下一场重新读取失败时保留结算，不暗中改用普通对手。

## 比赛期间专心陪玩

开始比赛时取得所选实例的专属占用，并切换到它自己的安静待机动作。占用期间由dsh-pet暂停自主动作、走动、自动碎碎念和工作状态插播；AgentGamer只显示游戏公开发言、人工测试提示与胜负反馈。减少动效时保持静止，不请求待机或反馈动画。

- 从第一局开始持续到整场结束，包含局间等待、人类思考、Agent模型暂停／出错期间。切换页面或刷新浏览器保留Host对局，也保留占用。
- 比赛发言借用同一占用，不再每说一句话就解锁。每3秒以原占用编号续期，租期15秒，不新增模型请求。
- 整场胜负反馈后约1.5秒释放；中途返回大厅、卸载活动游戏或关闭插件立即清理。游戏初始化失败也释放，避免没有比赛却一直占用。服务突然退出／网络故障时，原生客户端按最后租期最多15秒自动恢复。
- 用户点击／拖拽／隐藏桌宠等接管操作优先。续期失败后不自动新建占用，游戏继续；工具区显示原因与“恢复专心陪玩”，只有点击才重新尝试。其他插件已占用、桌宠休息或接口离线也会提示，不强制抢占。
- 大厅聊天仍只短暂占用，完成后恢复日常行为；不会把桌宠配置中的随机动作或碎碎念永久关掉。手动“告诉桌宠”仍走独立原生聊天入口，与比赛占用分开。

## 气泡与动作反馈（0.1.5）

0.1.4 只接入资料，普通游戏发言发生在专用游戏会话里，桌宠本体没有收到表现事件。0.1.5 增加直接表现同步：

- Agent 经 `agentgamer_say` 公开发送的文字／Emoji 原样进入桌宠气泡，快速连续发言时待发送气泡保留最新一条；平台聊天仍保留全部消息。
- 成功连接时显示陪玩提示并从 `animations.clicks` 选择挥手／点击回应。整场胜负使用该宠物 `animations.events.workStatus` 中的成功／失落动作，缺失时回落到自己的点击回应池；没有动作池时只显示气泡。
- 减少动效关闭动作请求；气泡固定不自动念出。气泡／动作是表现反馈，不宣称模型正在思考。
- 通过固定 `broadcast / anim` 路由，不经过 `chat / whisper`，不额外调用模型、不写原生聊天记忆。只有“告诉桌宠”的战报发送仍调用原生聊天模型并写记忆。
- 大厅同步仅短暂持有自己的占用锁，完成后即释放，异常时最多4秒过期；比赛期间借用上节的持续占用。已被其他互动占用时不抢锁；用户拖拽接管后停止当前反馈，不自动重放。桌宠休息时不主动叫醒。
- 大厅／牌桌显示请求同步状态，按钮“测试桌宠反应”可重新发送连接提示。显示“动作已请求”只代表接口受理，素材文件损坏或桌宠客户端未启动时仍需要检查 dsh-pet 的播放端。
- 更换伙伴、返回大厅、下一场和关闭插件会丢弃待发送的旧表现。已提交到桌宠端的气泡和短动画由它自己完成，不清空其他来源的气泡、不修改配置或日常动画。

## 资料与上下文

- 通过官方 [HTTP API](https://github.com/PC2005-cloud/dsh-pet/blob/main/API.md) 读取合并配置与指定实例的聊天窗口。实例 `whisperPrompt` 优先，空白时回落种类人设；按 `entry / petId` 绑定，不按显示名匹配。
- 人设完整进入稳定系统提示词，上限 **8 KiB UTF-8**。超限不静默截断，必须在预览中精简“陪玩人设副本”。副本仅在此次插件运行中使用，不写回桌宠。每场重新读取原资料，若存在副本则继续使用该副本；在预览中恢复原文后重连可解除副本。
- 近聊尊重 `chatMemoryRounds`，最多最近 **10 轮／4 KiB JSON**。0 不读取聊天；只接收成对的用户／助手纯文本，超限移除最旧完整问答，不导入图片、附件、动作和表情图片元数据。
- 近聊与最近20条已处理平台聊天、最近3场公开结果，共享已有 **12 KiB** 检查点总预算。按时间移除完整条目，不调用模型写摘要，不改写原始桌宠记忆。预览显示来源预算下保留的问答；后续检查点可能为较新的游戏消息腾出空间。
- 人设只影响称呼、性格、说话方式。工具仍只有 `agentgamer_read_rules / agentgamer_observe / agentgamer_act / agentgamer_say`；导入文本不能扩大文件、网络、其他会话权限，不能取得暗牌、对方有效骰面或随机状态。
- 同一伙伴连续比赛和切换游戏复用专用会话。比赛外更换伙伴或切回普通对手，新建专用会话；投递游标和公开比赛摘要按伙伴隔离。平台聊天仍可查看所有伙伴的消息，每条显示名固定在发送时。

导入资料会进入专用 DSH 会话的原始日志，遵循 DSH 自身保存设置。关闭 Host 后不会自动恢复对局或伙伴控制权；历史仍可查看。不要把不希望留在 DSH 历史中的内容导入游戏。

## 手动战报与异常恢复

战报由 Host 确定性生成，只包含游戏名称／版本、公开胜负、比分或最终筹码变化和稳定 `AG-…` 标识。不会附带聊天正文、骰子、牌靴、种子、推理或工具日志。未点击的战报只在内存中存在。

点击后，目标伙伴与文本固定，任务在后台执行，可以继续下一场。重复点击返回同一个任务；即使此时已更换伙伴，也只发送到原比赛绑定的实例。发送前重新检查目标，删除目标不会将战报转投其他宠物。

| 状态             | 可用操作                                 |
| ---------------- | ---------------------------------------- |
| 尚未发送         | 预览、告诉桌宠、复制                     |
| 等待发送／发送中 | 查看状态；可继续游戏                     |
| 已写入           | 查看公开回复、复制                       |
| 明确失败         | 排除原因后手动重试；重试前先核对原生记录 |
| 结果未知         | 核对桌宠记录、复制；不自动再次发送       |

dsh-pet 0.4.7 的聊天接口没有请求去重字段。AgentGamer 以稳定标识及完整战报文字核对原生用户／助手成对记录；断线后若已写入，则直接确认。请求中断且找不到确认时不能推断未送达，保留“结果未知”。过久的战报可能已超出原生接口最近200轮可读范围；此时复制战报或人工核对，不盲目补发。

已点击任务保存到 `resolveDshHome()/agentgamer/report-outbox.json`，含公开战报、目标身份、发送状态和公开回复。重启后未确认任务转为“结果未知”，不会自动 POST；打开大厅后可核对。损坏队列停止写入，保留原文件以避免重复发送。要清理持久战报，请关闭对应 Host、备份后自行删除此文件；删除后无法再靠原队列去重。开发配置可通过 Host 插件 `dataDirectory` 指定独立目录。

平台比赛和聊天、未点击战报及导入近聊仍仅在内存中；DSH 原始历史及 dsh-pet 原生聊天按各自保存策略管理。

## 适配接口与开发验证

`CompanionAdapter` 在 Host 实现发现、预览、发送和回执查询。`DshPetAdapter` 从当前 Host 的 `webServer.getOrigin()` 获取回环地址，访问固定 `/dsh-pet-7340/config`、`/chat?pet=…&rounds=…` 和 POST `/chat?pet=…&surface=any`，表现接口 `broadcast / anim` 及占用接口 `lock / lock/release`。客户端不能指定目标 URL；不直接读写 dsh-pet 配置或原生聊天文件。`surface=any` 接受该实例已有的 web／desktop 显示端，不改变显示配置。

Remote 新增 `companions / companionPreview / reports / shareResult / retryReport / checkReport / testCompanionReaction / resumeCompanionFocus`；`configure` 可选 `companion:{entry,petId}|null` 及 `personaOverride`。省略 `companion` 保留当前伙伴，null 切回普通对手。占用编号仅由Host持有，不进入Remote快照、游戏观察或模型上下文。游戏 SDK API 仍为1；视图与记录可选接收 `opponentName`，旧扩展可忽略。

根构建脚本覆盖适配器、严格记忆预算、伙伴隔离、公开战报和发送故障测试。`scripts/ui-companion-check.js` 通过 Playwright CLI 对已启动的**隔离** DSH 和真实 dsh-pet 0.4.7 进行页面与原生记忆联调，需要 `fishA / fishB` 两个合成实例及本地 `agentgamer-mock` 模型。模拟模型不访问供应商 API；测试配置不得指向日常 DSH_HOME。`scripts/mock-provider.mjs` 可通过 `AGENTGAMER_PET_METRICS_PATH` 输出不含原始提示正文的调用类别、工具范围、合成身份标记及输入字节，检查战报仅在手动发送时调用模型。

第三方记忆提供者、自由指挥动作、语音和外部 Agent 不在本轮支持范围。真正模型策略、日常人设表现和供应商用量由用户试玩确认。
